# PlasmaBENCH data archive

Synthetic ground-truth data for benchmarking DIA software (DIA-NN, FragPipe) on
TimsTOF mixed-proteome plasma, generated with **TimSim**.

- **Code & instructions:** https://github.com/theGreatHerrLebert/PlasmaBENCH
  (see `REPRODUCE.md` for the step-by-step reproduction guide)
- **DOI:** 10.5281/zenodo.20733913
- **License:** CC-BY-4.0
- **Reproduces in silico:** Distler et al., *Nat Commun* 2025,
  DOI 10.1038/s41467-025-64501-z (data PXD056598)

## The PYE1 design

Two samples, fixed human-plasma background, complementary spike-ins:

| Species | Sample A | Sample B | Expected B/A |
|---|---|---|---|
| Human (plasma) | 90 % | 90 % | 1.00 |
| Yeast | 2 % | 6 % | 3.00 |
| *E. coli* | 8 % | 4 % | 0.50 |

TimSim emits a per-precursor **blueprint** (`synthetic_data.db`) alongside every
simulated `.d`, so recall, FDR, and ratio recovery are scored against exact truth.

## What's in this record

Three tarballs. **Download into the PlasmaBENCH repo root and unpack** — they
recreate the directory layout the analysis scripts expect:

```bash
zstd -d --stdout plasmabench-data-raw.tar.zst    | tar -xf -
zstd -d --stdout plasmabench-simulations.tar.zst | tar -xf -
zstd -d --stdout plasmabench-results.tar.zst     | tar -xf -
sha256sum -c SHA256SUMS
```

| File | Unpacks to | Contents |
|---|---|---|
| `plasmabench-data-raw.tar.zst` | `data/raw/` | search FASTA; the blank `.d` (noise source); the real G PYE1 `.d`s; FragPipe DDA inputs |
| `plasmabench-simulations.tar.zst` | `simulations/` | simulated Sample A/B `.d`s; **`synthetic_data.db` blueprint (ground truth)**; seeds; rendered configs |
| `plasmabench-results.tar.zst` | `results/` | our DIA-NN 1.8 / 2.5 / 2.6 reports (`report.tsv`/`.parquet`, stats, `.quant`) |

## What is NOT included (by design)

- **Search-engine binaries.** DIA-NN and FragPipe have their own licenses —
  install your own (the repo's `REPRODUCE.md` and `scripts/get_diann.sh` help).
- **Predicted spectral libraries** (`*.predicted.speclib`, ~20 GB). They are
  regenerated by the search engine; excluding them keeps the archive lean.

## How to use it

After unpacking, follow `REPRODUCE.md` in the code repo. Quickest path — replay
the figures/metrics from the included reports:

```bash
make venv && source .venv/bin/activate
make stage1-eval   # and stage2-eval, quant-eval, real-vs-sim-eval, lowinput-eval, idoverlap-eval
```

To re-search the simulated `.d`s with your own engines, or to regenerate the
simulations from the seeds with TimSim, see tiers 2–3 of `REPRODUCE.md`.
